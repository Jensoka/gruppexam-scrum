# Reflektion – Agil utveckling och Scrum

### 1. Vad är agil utveckling, och vad i ert arbetssätt den här veckan var agilt?

Agil utveckling handlar om att arbeta stegvis, ha korta feedbackcykler och kunna anpassa sig efter förändringar under projektets gång. Genom att kontinuerligt uppdatera sprinttavlan kan gruppen följa arbetet, upptäcka problem och hantera eventuella ändringar.

Under veckan har vi arbetat agilt genom att hålla dagliga standups (dailys), där vi diskuterat vad vi gjort, vad vi planerat att göra och om vi stött på några hinder. Vi har även haft en bra kommunikation kring möten, Pull Requests och kodgranskningar. Detta har gjort det lättare att samarbeta och hålla alla uppdaterade om projektets utveckling.

### 2. Vilka Scrum-roller och moment använde ni?

Vi utsåg en Scrum Master och tilldelade samtliga gruppmedlemmar utvecklarroller.

Vi planerade in dagliga standups där varje medlem fick berätta hur arbetet gick, vad dagens planer var och om det fanns några hinder. Vi använde även en sprinttavla för att fördela och följa upp våra User Stories.

Arbetet delades upp i mindre uppgifter som tilldelades gruppmedlemmarna. På så sätt kunde vi arbeta parallellt och samtidigt ha en gemensam överblick över projektets framsteg.

### 3. Beskriv hur en User Story gick från Att göra till Klart hos er.

När en User Story tilldelades en utvecklare började arbetet med att skapa en separat branch från `main`. Utvecklaren implementerade sedan den efterfrågade funktionen i sin branch.

När arbetet var färdigt pushades branchen till GitHub och en Pull Request skapades. Därefter fick en annan gruppmedlem granska koden genom en så kallad *peer review*.

Om koden godkändes kunde Pull Requesten mergas in i `main`. När ändringen var integrerad markerades User Storyn som klar på sprinttavlan.

## 4. Vad är en merge-konflikt, när uppstår den och hur löser man den på GitHub?

En merge-konflikt uppstår när Git inte automatiskt kan kombinera ändringar från olika branches. Det händer exempelvis när två utvecklare har gjort olika ändringar i samma del av en fil.

Ett exempel kan vara att två utvecklare arbetar med samma funktion i `index.html`, exempelvis `funktion4()`. Den ena utvecklaren ändrar funktionens innehåll medan den andra gör en annan ändring på samma rader. När båda försöker få in sina ändringar i `main` kan Git upptäcka en konflikt.

Under veckan har vi fokuserat på att samarbeta via separata branches och Pull Requests för att minska risken för konflikter.
